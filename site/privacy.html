Privacy Policy

CueParcel reads the page you ask it to read, works on it inside your browser, and copies the result for you.

Nothing CueParcel processes is sent anywhere by CueParcel. There is no server, no account, no analytics and no telemetry, and captured page content is not kept after your browser session ends.

Applies to the CueParcel browser extension, version 1.1.0. Last updated 14 February 2026.

This page is the canonical public privacy policy. It is published from site/privacy.html in the CueParcel repository, and it describes what the extension's code actually does.

The short version

CueParcel accesses webpage content at your request. It does not collect it: nothing is received by the developer, stored off your device, or shared with anyone.

  • No backend
  • No telemetry
  • No analytics
  • No account or API key
  • Session-only capture storage
  • No host permissions

CueParcel is not a chatbot, a summariser, or an agent runner. It does not call an AI model, does not generate answers, and does not require an API key. It prepares and copies context; you decide where that context goes.

What is accessed, and when

Access happens only after an explicit action by you. There is no background capture, no scheduled capture, no always-on page access, and no capture of any tab you did not activate.

  • You click the CueParcel toolbar icon (or press the Alt+Shift+Y shortcut) while a page is focused. The content of that active tab only is read. That click is also what grants the activeTab permission for that page.
  • You use Context Lens on an already-captured page. The visible regions of that same page are outlined so you can click the sections to include.
  • You select text on the page and add it. Only the text you selected is used.

Nothing is read at any other time. CueParcel cannot read a page you have not activated, and it does not enumerate, list, or visit your tabs or your browsing history.

What is extracted is a structured document: title, headings, paragraphs, lists, code blocks, tables, quotes and link targets. Specialised adapters recognise GitHub issues, GitHub pull requests and technical documentation pages; everything else goes through a generic article extraction. The page's raw HTML is not kept as a stored artefact — what is kept is the derived, structured representation.

Where that data is processed

Entirely locally, inside your browser, inside the extension.

  • There is no CueParcel backend, server, or API. No CueParcel-operated system receives anything, because no such system exists.
  • The extension makes no network requests of its own. The published audit found no fetch, XMLHttpRequest, WebSocket, sendBeacon or dynamic import anywhere in the extension's source or its shipped bundle. The only http strings in the shipped package are SVG XML namespace declarations.
  • Extraction, cleaning, Markdown and JSON serialisation, size estimation and receipt generation all run as ordinary in-browser code.
  • The extension does not contact an AI provider. If you paste the result into an AI tool later, that is your action, under that tool's own privacy policy.

Does captured content leave the browser?

Not by CueParcel. Never. CueParcel does not transmit, upload, sync or report your content, and there is no channel in the code for it to do so.

Three ways content moves, all of them deliberate and all of them yours:

  1. Copy

    When you press Copy, the packaged text is written to your system clipboard. From that moment it is in your clipboard, under your control and your operating system's rules. CueParcel never reads your clipboard.

  2. Download

    When you press Download, the text is saved to a local file through an object URL created in the page. CueParcel does not request the downloads permission and does not track what you saved.

  3. Your subsequent paste

    If you paste the copied text into another application — an AI assistant, an editor, a ticket — the content goes wherever that application sends it. That transfer is not performed by CueParcel and is governed by that application's privacy policy, not this one.

Storage

This is the complete list of what CueParcel writes, and where.

For the current browser session only

Written to chrome.storage.session, cleared when you close the browser:

  • Your captured document for a window — the derived, structured content shown in the panel. At most one captured document per browser window is cached.
  • Capture bookkeeping: capture id, tab id, URL, title, capture time and status.
  • Your Context Cart — the sources you collected for the current task, one entry per browser window.

Kept until you remove it

Written to chrome.storage.local:

  • One boolean recording that you dismissed the "pin CueParcel" onboarding card, under the key page2agent.onboarding.pinDismissed.v1. It contains no page content. It is removed when you uninstall CueParcel or clear its extension data.

That is the whole list. In particular:

  • Captured page content is never written to chrome.storage.local. It is not persisted to disk as part of normal use.
  • There is no cloud sync, no remote backup, and no export history.
  • There is no log of pages you visited, and no record of which sites you used CueParcel on.
  • The only durable value the extension stores is a single UI preference boolean containing no page content.

If you uninstall the extension, the browser removes both stores. If you want the session data gone sooner, close the browser (which clears chrome.storage.session) or clear the extension's data from your browser's extension settings.

Clipboard and export behaviour

  • Copy writes the packaged context to the system clipboard, and only when you press the button. CueParcel never reads the clipboard and is not a clipboard manager.
  • Download saves the packaged context as a local file (Markdown or TaskSpec JSON) using a browser-generated object URL, which is revoked immediately after the download starts.
  • Neither action sends anything over the network.

What happens to the copied or downloaded text after that point is outside CueParcel's control and outside this policy.

Telemetry, analytics and tracking

None. The extension has no mechanism to measure you, so nothing about your use of it is measured.

  • No analytics service or SDK.
  • No telemetry and no crash reporting.
  • No advertising or tracking code.
  • No usage counters, feature flags or A/B testing.
  • No unique identifier of any kind — no installation id, no device id, no advertising id.
  • No cookies: the extension does not request the cookies permission, does not read document cookies, and does not set any.

Backend, third parties and data sales

  • Backend: none. There is no server component to this product, hosted or self-hosted.
  • Third-party sharing: none. No data is sold, rented, traded, disclosed or transferred to any third party, because no data reaches the developer or any service operated on the developer's behalf.
  • Sale of data: none. Your data is not a product here, and nothing is monetised through it.
  • Third-party code. The extension bundles open-source runtime libraries — React and @mozilla/readability — at build time. They are compiled into the submitted package, run locally, make no network requests, and being bundled means there is no remotely loaded code of any kind.
  • No affiliation. CueParcel is an independent open-source project. It is not affiliated with, endorsed by, or acting on behalf of any AI provider, browser vendor or hosting service.

Retention

  • Captured page content, capture bookkeeping and the Context Cart: browser session only — gone when the browser closes.
  • The onboarding dismissal boolean: until you uninstall the extension or clear its data.
  • Anything on a server: nothing, because no server exists.
  • Backups, archives and analytics history: none exist.

The developer holds no copy of your content at any point, so there is nothing for the developer to retain, delete or disclose on request.

Permissions, and why each one is needed

CueParcel requests exactly four permissions. It requests no host permissions: the submitted manifest has no host_permissions key, so the extension cannot read any site until you activate it on that site.

  • activeTab — read the current page only after you click the toolbar icon or press the shortcut. This is what makes capture possible without broad site access.
  • scripting — inject CueParcel's own packaged content script into the page you activated, which performs extraction and draws the Context Lens selection overlay.
  • sidePanel — show CueParcel's interface in the browser's Side Panel beside the page, so your source stays visible while you work.
  • storage — keep the capture and the Context Cart for the current browser session, so a page navigation or a service-worker restart does not lose your work.

CueParcel does not request and does not use <all_urls>, tabs, cookies, history, bookmarks, webRequest, downloads, nativeMessaging, or clipboard read access.

It does not run code fetched from the internet: no remote code, no remote JavaScript, no eval, no new Function, and no dynamically loaded script. The extension's content security policy is script-src 'self'; object-src 'self';, which blocks remotely hosted scripts.

Security posture

  • Page content is treated as untrusted input. CueParcel separates source content from CueParcel-generated instructions in its data model and in every output, so instructions that happen to appear inside a webpage cannot be presented as if CueParcel wrote them.
  • Un-sanitised page HTML is never injected into the extension's privileged panel.
  • Data crossing between the page, the extension's service worker and the panel is validated before use rather than trusted by type.

This describes how the product is built. It is not a security certification, and CueParcel has not undergone a formal third-party security audit.

Children

CueParcel is a general-purpose productivity tool. It is not directed at children, does not knowingly collect information from anyone, and has no account, profile or communication feature.

Your choices and control

  • Do not activate it. If you never click the icon, CueParcel never reads a page.
  • Capture only what you want. Context Lens exists so you can include the sections you mean and leave everything else out.
  • Inspect before you copy. The Context Receipt lists what is in the package and what is not.
  • Close the browser to clear all session-stored capture data, or clear the extension's data to remove the stored preference.
  • Uninstall to remove everything CueParcel ever stored locally.

Changes to this policy

If a future version of CueParcel changes what it accesses, stores or transmits, this policy will be updated before that version is released, the "Last updated" date above will change, and the change will be visible in this repository's history. CueParcel's principle is that the policy describes the code; if the code changes, the policy changes with it.

Verifying this policy

Every claim here is checkable. This is the audit it rests on; the full version is published in the repository at docs/store/edge/AUDIT.md.

  • Access requires an explicit user action — the extension's only capture path begins at the toolbar click handler.
  • No network requests — no fetch, XMLHttpRequest, WebSocket, sendBeacon or dynamic import exists in the extension source or its shipped bundle.
  • No remote code — no eval, no new Function, no remotely loaded script; the content security policy is script-src 'self'.
  • No analytics or telemetry — no analytics dependency and no reporting code path.
  • Session-scoped capture storage — captured content is written to chrome.storage.session only.
  • Exactly one durable local value — the boolean key page2agent.onboarding.pinDismissed.v1 in chrome.storage.local.
  • Four permissions, no host permissions — stated verbatim in the submitted manifest.json.
