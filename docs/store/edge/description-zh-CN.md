## 字数核算

只取两个标记**之间**的行，去掉两端的分隔空行，用 `\n` 连接后读取 `.Length`。
这正是审核人员粘贴进合作伙伴中心描述框的那段文本，因此该数值就是商店实际看到
的数值。

```powershell
function Get-Body([string]$path) {
  $lines = Get-Content -LiteralPath $path
  $s = [Array]::IndexOf($lines, "--- LISTING BODY ---") + 1
  $e = [Array]::IndexOf($lines, "--- END LISTING BODY ---")
  $seg = $lines[$s..($e-1)]
  while ($seg.Count -gt 0 -and $seg[0].Trim()  -eq "") { $seg = $seg[1..($seg.Count-1)] }
  while ($seg.Count -gt 0 -and $seg[-1].Trim() -eq "") { $seg = $seg[0..($seg.Count-2)] }
  $seg -join "`n"
}
(Get-Body "docs/store/edge/description-zh-CN.md").Length
```

**挑出真正重要的内容，再交给 AI。**

面对一个网页，通常只有两个选择：把整页内容粘过去，其中大部分与问题无关；或者
只发一个链接，然后听天由命。CueParcel 给出第三种做法——挑出真正有用的部分，把
多个来源组合起来，说明你希望 AI 做什么，并在复制之前先看清这份上下文里到底有
什么。

**工作方式**

1. **抓取你正在读的页面。** 点击 CueParcel 图标，侧边栏会在页面旁边打开，来源
   内容始终可见。
2. **挑出真正重要的部分。** 用 **Context Lens** 直接在页面上点击要收录的区域——
   安装说明、某条警告、一张参数表——而不是整篇文档。
3. **用 Context Cart 汇集多个来源。** 同一个任务里可以同时放入 issue、pull
   request 和文档页面。每一项都保留自己的 URL、标题与来源类型，不会变成一段
   来历不明的文字。
4. **说明你想要什么结果。** 学习（Learn）、对比（Compare）、核实（Verify）、
   实现（Build）、修复（Fix）——每个配方会自己判断需要几个来源，并在来源不足时
   明确告诉你。
5. **发送之前先读一遍。** 结果可以按 Agent 提示词、Markdown 或 JSON 格式的
   **TaskSpec** 复制或下载，由你自己带走。CueParcel 不会替你发送任何内容。

**Context Lens——是"挑"，不是"粘"**

Context Lens 只在你主动请求后才会在页面上运行。它会标出识别到的有意义区块——
标题、段落、列表、代码块、表格、引用块——你点选要收录的那些，没点的就不会被
带进去。你也可以把自己的划选文字作为额外的区域加入。界面会实时估算已选内容的
规模，让你清楚感受到"这一节"和"整个页面"之间的差距。

**Context Cart——组合多来源，保留出处**

Context Cart 保存为同一个任务收集的所有来源。来源在抓取时就已确定类型：GitHub
Issue、GitHub Pull Request、技术文档页面，或普通网页。**GitHub Issue**、**GitHub
Pull Request** 与**技术文档**由专用适配器解析其结构，其余页面走通用正文抽取。
每个来源都保留 URL、标题与角色，并单独列出，方便调整顺序或删除。

**五个配方**

- **学习（Learn）**——忠实地讲清所抓取的材料，保留来源自身的术语。
- **对比（Compare）**——把两个或更多来源并排分析：一致之处、差异、取舍，以及
  缺失的信息。
- **核实（Verify）**——区分来源真正支持的说法与并不支持的说法。
- **实现（Build）**——把抓取到的文档当作实现依据，不虚构文档中未说明的行为。
- **修复（Fix）**——针对已报告的问题，说明复现方式，并瞄准最小且可靠的修复。

每个配方都写明了它需要的最少来源数量，因此"对比"不会在你只放了一个来源时悄悄
运行。

**TaskSpec——机器可读的那一面**

除了可读的提示词，CueParcel 还会生成 **TaskSpec**：一份结构化的 JSON 文档，描述
任务本身、来源清单、适配器真正核实到的来源事实（仓库、issue 编号、状态、标签、
分支名）、规模估算，以及生成它的配方。页面上没有的事实会保持缺失，而不是被猜测
出来。当消费这份包的是另一个工具而不是人时，可以直接下载 JSON。

**Context Receipt——复制之前先检查**

**Context Receipt** 概述你即将发送的这份包：包含哪些来源、每个来源贡献了什么、
来源内容与生成内容的分界、规模估算，以及同样重要的一点——*没有*被包含的内容。
它还会列出被排除或无法核实的事实。在内容离开剪贴板之前，你可以先看清自己这份
上下文的边界。

**本地优先的设计**

- **只有你点击才会抓取。** CueParcel 没有后台抓取、没有定时任务、不会长期读取
  页面。
- **内容不会离开你的设备处理。** 没有 CueParcel 服务器、没有后端、没有账号、
  没有登录、不需要 API Key、也不做云同步。文本在扩展内整理完成，通过你自己的
  剪贴板带走。
- **没有统计分析，也没有遥测。** CueParcel 不统计你、不上报使用情况，内部没有
  任何追踪代码。
- **抓取到的页面内容仅限本次会话。** 内容只在当前浏览器会话中保留，浏览器关闭
  即清除，绝不写入本地永久存储。
- **四项权限，没有主机权限。** CueParcel 申请 `activeTab`、`scripting`、
  `sidePanel` 与 `storage`；不申请访问所有网站，也不使用 cookie、历史记录、
  书签或网络请求权限。
- **没有远程代码。** 所有运行的代码都打包在扩展内部。

完整说明见 https://kallist.github.io/CueParcel/privacy.html。

**适合谁使用**

适合所有与 AI 助手协作、却总在反复重打或重新粘贴素材的人：一边读 issue 一边翻
文档的开发者、需要比较两套方案的人、需要确认某个说法是否真有依据的评审者，以及
希望助手只回答"这一节"而不是整个互联网的人。

**CueParcel 不是什么**

CueParcel 不是聊天机器人，不是摘要工具，也不是 Agent 运行器。它不调用模型，不
需要 API Key。它只负责整理出一份结构良好的包并交到你手上，由你粘贴到平时使用的
任何工具里。你的来源不会因此公开，因为它们从未离开你的浏览器。

**快速上手**

安装 CueParcel 并固定到工具栏，然后打开任意普通网页，点击 CueParcel 图标。侧边栏
会在页面旁边打开：抓取页面、挑出你要的区域、加入 Context Cart、选择配方，并在
复制前查看 Context Receipt。按 Alt+Shift+Y 也可从键盘触发抓取。
